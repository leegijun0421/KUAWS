## 2026-08-27 — Google 경로 응답은 저장·캐싱하지 않는다

결정: `RouteProvider.cacheable` 로 프로바이더별 캐싱 정책을 나눈다.
Google 은 `False`(디스크에 일절 남기지 않음), ODsay 는 `True`.
이유: Google Maps Platform 약관은 응답의 사전 페칭·저장·캐싱을 금지한다
(Place ID 와 위경도만 예외적으로 영구 저장 가능). 반면 ODsay 는 Basic 무료 30회/일이라
개발 중 캐시가 없으면 한도를 바로 넘긴다. 두 제약이 정반대이므로 하나의 규칙으로 묶을 수 없다.
대안과 기각 사유:
- 전면 캐싱 — Google 약관 위반. 심사 대상 코드에 약관 위반이 남는 것은 감점 이상의 위험이다.
- 전면 캐싱 금지 — ODsay 무료 한도(30회/일)를 개발 중에 소진한다.
비고: Google 쪽 호출 수 절감은 캐시가 아니라 Haversine 사전 필터로 후보를 줄여서 해결한다.
`tests/test_routing_provider.py` 에 두 정책을 강제하는 테스트를 두었다.

## 2026-08-27 — 대상 지역을 부산에서 화이트리스트 글로벌 도시로 변경 (2026-08-21 결정 대체)

결정: 데모·지원 대상을 부산 단일 도시에서 데이터 품질을 검증한 글로벌 도시 화이트리스트로
바꾼다. 검증 대상은 도쿄·파리·방콕(방콕은 품질 하한 측정용)이며 8/30 스모크 테스트에서 확정한다.
이유: 국내 한정 데이터원(ODsay·TourAPI)에 묶이면 서비스 확장성 평가에서 불리하다.
POI 는 Google Places 단일 소스로 통일한다.
대안과 기각 사유: 부산 유지 — 2026-08-21 에 "대중교통 밀집 도심이라 경로 상세가 드러난다"는
이유로 선정했으나, 확장성 논거를 포기하는 대가가 더 크다고 판단했다.
비고: 지원 도시를 명시적으로 제한하는 것은 약점이 아니라 성숙도로 프레이밍한다
("데이터 품질을 검증한 도시만 지원"). 이 결정은 Notion "챌린지 일정" DB 에 먼저 기록되어
있었고, 이 문서에는 8/27 에 뒤늦게 반영했다 — 앞으로 결정은 양쪽에 동시에 남긴다.

## 2026-08-27 — 경로 API는 프로바이더 추상화로 국내/해외를 분리한다

결정: `RouteProvider` 인터페이스를 두고 국내 구간은 ODsay, 해외 구간은 Google Maps
Directions 로 분기한다. 좌표가 한국 경계 상자 안이면 ODsay, 아니면 Google 이다.
이유: Google 공식 커버리지 표상 대한민국은 도보·자동차·자전거 경로가 모두 미지원(`—`)이다
(고정밀 지도 반출 제한). 지원 도시가 해외 위주여도 국내 도시를 하나라도 넣는 순간 Google 만으로는
경로 상세가 죽으므로, 구체 API 를 인터페이스 뒤에 격리해 두면 그때 어댑터만 추가하면 된다.
대안과 기각 사유:
- 구체 API 직접 호출 — 라우팅 백엔드 교체 시 스케줄러까지 고쳐야 한다.
- ODsay 단독 — 국내 한정이라 서비스 확장성 평가에서 불리하다.
비고 1: 2026-02-27 국토지리정보원이 조건부 반출을 허가했으나 서비스 정상화 시점은
미공지다. 규제가 풀려 Google 이 국내 경로를 지원하게 되면 어댑터 하나만 교체하면 된다.
비고 2: 이 항목의 최초 초안은 데모 도시를 부산으로 전제했으나, 팀은 이미 화이트리스트
글로벌 도시로 전환한 상태였다(아래 항목). 근거를 그에 맞게 정정했다.
비고 3: ODsay 어댑터의 실사용 여부는 8/30 스모크 테스트 게이트에서 화이트리스트가
확정된 뒤 결정한다. 화이트리스트에 국내 도시가 없으면 어댑터는 참조 구현으로만 남긴다.

## 2026-08-27 — LLM은 AWS Bedrock 대신 Anthropic Claude API를 직접 호출한다

결정: `anthropic` SDK로 Claude API를 직접 호출한다. Bedrock(boto3) 경로는 제거했다.
이유: "AWS가 제공하는 LLM API를 써야 한다"는 주최측 안내가 잘못된 것으로 확인되어,
제약이 없어졌다. 다이렉트 API가 설정이 단순하고(키 1개), 모델 액세스 승인 대기가 없으며,
최신 모델(claude-sonnet-5)을 바로 쓸 수 있다.
대안과 기각 사유: Bedrock — IAM/리전/모델 액세스 승인 절차가 예선 속도를 깎는다.
provider 스위치 래퍼 — 되돌릴 이유가 사라졌으므로 불필요한 추상화.

## 2026-08-23 — Kiro 협업은 Git + 파일 소유권 방식으로 한다

결정: 실시간 동시 편집 대신 모듈별 파일 소유권 + 짧은 브랜치 + `.kiro/` 공유로 협업한다.
이유: Kiro에는 실시간 공동 편집 기능이 없다. 에이전트는 한 작업에 파일 10개 이상을
건드리므로, 경계를 명시하지 않으면 5인 팀에서 충돌이 폭증한다.
대안과 기각 사유: Kiro Crew — 6주 예선에 새 인프라 세팅은 오버엔지니어링. 본선에서 재검토.
