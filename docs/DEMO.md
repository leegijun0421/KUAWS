# 데모 시나리오 3종 · 리허설 · 녹화 fallback · 3분 영상 대본

> W4 "[W4] 데모 시나리오 3종 사전 리허설 + 화면 녹화 fallback", "[W4] 데모 영상 촬영 (3분)".
> Google 약관상 결과(경로 응답)를 파일로 저장해 둘 수 없으므로, **실제로 돌린 화면을 녹화**해 둔다.
> 발표 중 API 장애·네트워크 불안정 시 이 영상으로 대체한다.

## 시나리오 3종 (전부 파리 — Notion W4)

| # | 입력 (`tests/fixtures/conversations/`) | 일수 | 보여줄 것 |
|---|----------------------|------|-----------|
| 1 | `01_clean_demo.txt` (깔끔한 3인) | 2일 | **발표 메인.** 기본 흐름 전체 — 근거 인용, 루브르·오르세(꼭 갈 곳) 포함, 점심·저녁 시간 식사, 실제 편성 시각, 상세 |

(발표 PC 에서 재생하기 쉽게 mp4 로 바꾼 사본도 같은 폴더에 둔다).

## 장애 대응 (발표 중 — 외워 둘 것)

| 상황 | 대응 |
|------|------|
| API 응답이 10초 넘게 안 옴 | 5초 더 기다리고 "네트워크가 느리네요, 녹화본으로 보여드리겠습니다" |
| 에러 화면 | 즉시 영상 전환. 사과하지 않는다 |
| 발표장 네트워크 없음 | 처음부터 영상으로 진행 |
| 결과가 리허설과 다름 | 그대로 진행 — "실시간 시간표라 매번 조금씩 다릅니다"(실호출이라는 증거) |

## 사전 점검 (발표 전날 · 당일 아침)

- [ ] `.env` 에 `ROUTING_MOCK`, `LLM_OFFLINE` 이 비어 있다(모의 경로 금지)
- [ ] `GET /api/planner/cities` 의 `dataSource` 가 두 도시 모두 `collected`
- [ ] 수집 좌표 만료일(`data/processed/pois/<city>/meta_<city>.json` 의 `coord_expires_at`, 10/27) 이전
- [ ] 출발일은 **오늘 기준 100일 이내**(Routes API 제한). 기본값(오늘+18일)을 그대로 쓴다
- [ ] 키 A 가 발표 장소 네트워크 IP 에서 동작하는지(IP 제한!) — 아니면 핫스팟 또는 녹화본 사용
- [ ] 브라우저 확대 100%, 알림 끄기, 창 1280×800 이상
- [ ] 녹화본 3개(`Claude outputs/demo/demo_*.webm`)를 발표 PC 로컬에 복사, 재생 앱까지 미리 열어 둠

## 녹화 방법 (자동)

```powershell
# PowerShell, C:\project\KUAWS — 처음 한 번
pip install playwright
python -m playwright install chromium

# 터미널 1
uvicorn backend.main:app --port 8000
# 터미널 2
cd frontend; npm run dev
# 터미널 3
python scripts/e2e_check.py --repeat 3   # 시나리오별 3회 실행: 소요 시간·호출 수·결과 편차
python scripts/record_demo.py            # 3종 녹화 + 단계별 소요 시간 출력
```

스크립트가 화면 하단에 자막을 띄우며 진행하므로 녹화본 자체가 설명을 담는다.
출력된 “취향 추출 / 일정 생성” 소요 시간을 아래 리허설 기록에 옮긴다.

## 제출 영상 — 완성본 `Claude outputs/demo/KUAWS_demo_3min.mp4` (2:16, 9/27 실호출 녹화)

| 구간 | 내용 |
|------|------|
| 0:00–0:24 | 제목 → 문제("평균 내면 모두 불만, AI 는 없는 시간표를 지어냄") → 해결 한 줄 |
| 0:24–1:06 | 시연 1: 시나리오 2(취향 정반대) — 대화 → 취향 → 만족도 막대 → 실제 시간표 → 장소별 멤버 만족도 |
| 1:06–2:02 | 시연 2: 시나리오 3(알레르기·11시 제약) — 조건 반영 → 운영기관 표기 → 링크 공유 → 친구 화면 재계산 |
| 2:02–2:16 | 실측 결과(15/15 성공, 48구간 실제 편성 시각, 3~6초) → 마무리 |

녹화본에서 바꾼 것: 시나리오 3 결과 자막을 "해산물 식당은 빠졌습니다" → "해산물 식당 제외 조건 적용"으로 덮어썼다
(이번 수집본에는 걸리는 식당 이름이 없어 실제 제외는 0곳이었다 — 과장하지 않는다).
발표 fallback 용 mp4 3개도 같은 폴더에 있다(`demo_1_clean.mp4` 등).

### 원래 대본 (내레이션을 넣어 다시 만들 때)

자막 필수, 알고리즘 용어 금지(“maximin” → “가장 아쉬운 사람이 없게”). ★ = 점수가 나오는 장면.

| 시간 | 화면 | 자막·내레이션 |
|------|------|---------------|
| 0:00–0:25 | 제목 카드 → 단톡방 캡처 | 친구 셋이 여행을 가면, 가고 싶은 곳이 다 달라요. 단톡방에서 며칠을 싸워도 결국 누군가는 양보하죠. |
| 0:25–0:40 | 서비스 이름 | 모두의 여행 — 대화를 붙여넣으면 아무도 소외되지 않는 일정을, 진짜 지하철 시간표에 맞춰 만들어요. |
| 0:40–0:55 | 대화 붙여넣기 → 분석 | 실제 대화를 그대로 넣습니다. |
| 0:55–1:10 | 취향 카드·근거 인용 | 세 사람의 취향을 읽었어요. 한 명은 많이 걷고 싶고, 한 명은 조용히 쉬고 싶대요. 틀리면 직접 고칠 수 있어요. |
| 1:10–1:25 | 슬라이더 하나 수정 → 일정 만들기(로딩 1.5배속) | 확실하지 않은 것만 한 번 확인하고 일정을 만듭니다. |
| 1:25–1:50 | ★ 결과 — 장소마다 멤버 막대 | 평균이 아니라, **가장 아쉬운 사람**의 만족도부터 올렸어요. 누가 얼마나 만족하는지 장소마다 보여요. |
| 1:50–2:10 | ★ 이동 카드 확대 | 몇 시 몇 분에 어느 노선을 타고, 어디서 갈아타는지 — **실제 시간표**예요. 운행 회사도 함께 표시돼요. |
| 2:10–2:20 | ★ 위험 문장 / 경치 대안 | 환승이 빠듯한 곳은 미리 알려주고, 조금 돌아가도 공원을 지나는 길도 골라 줘요. |
| 2:20–2:50 | 공유 링크 → 다른 화면에서 열기 | 링크 하나로 공유하면, 친구 화면에서도 최신 시간표로 다시 열려요. 지금은 파리와 타이베이를 지원해요. |
| 2:50–3:00 | 마무리 카드 | 아무도 소외되지 않는 그룹 여행, 모두의 여행. |

시연 구간(0:40–2:50) = 130초 ≥ 100초. 영상 파일: `Claude outputs/demo/demo_3min.mp4`
(녹화본 `demo_2_conflict.webm` + 공유 장면(`demo_3_constraints.webm` 끝부분) + 제목·마무리 카드).
에러 화면·개발자 도구가 보이면 다시 녹화한다. 로딩은 배속만 하고 잘라내지 않는다.
