# PoC 문서 — 모두의 여행 (AI 그룹 여행 플래너)

> 고려대학교 x AWS AI Innovators Challenge (AI Tech Day 2026) 예선 제출물 · KUAWS 팀
> 저장소: https://github.com/leegijun0421/KUAWS

## 1. 한 줄 요약

단톡방 대화를 붙여넣으면, LLM 이 사람별 취향과 절대 조건을 읽고, **가장 손해 보는 사람의 만족도를
최대화**하는 장소를 **실제 대중교통 시간표** 위에 배치해 링크 하나로 공유한다.

## 2. 문제 정의

| 현상 | 근거 |
|------|------|
| 그룹 여행 일정 조율은 카톡·스프레드시트 수작업 | 팀원 5명 전원의 경험, 기존 플래너는 1인 입력 전제 |
| 취향을 평균 내면 아무도 만족하지 않는다 | 정반대 2인 대화(`mocks/chats/03`)에서 평균 1위 = 둘 다 그럭저럭인 장소 |
| LLM 단독 일정은 대중교통을 지어낸다 | 노선·편성 시각·환승은 LLM 이 검증할 수 없는 사실 데이터 |

## 3. 해결 — 핵심 기능 6가지

1. **대화 → 취향**: 단톡방을 화자별로 나눠(규칙) 1회 LLM 호출로 5축 취향·신뢰도·하드 제약·꼭 갈 곳을 추출.
   신뢰도 < 0.6 인 축만 슬라이더로 되묻는다. LLM 장애 시 키워드 규칙으로 폴백.
2. **정규화 maximin 매칭**: 멤버별 적합도를 각자의 최고값으로 정규화한 뒤 최저값을 최대화.
3. **제약 스케줄러**: 실제 편성 시각 기반 배치, 12·18시 식사, 요일별 영업시간, 체력 기반 이동 상한, 막차 경고.
4. **실패 위험도**: 환승 연결 여유(실제 시간표)·영업 종료 여유·식사 피크·최저 적합도 — 객관 지표만.
5. **경치 대안 경로**: 같은 호출의 대안 경로 주변 자연·명소 태그로 점수화, "+N분 경치" 병기.
6. **링크 공유**: 입력 + Place ID 순서만 저장, 열 때 최신 시간표로 재계산(약관 준수).

## 4. 기술 구조

→ [ARCHITECTURE.md](ARCHITECTURE.md) (다이어그램·수식)

- 백엔드 FastAPI · 프론트 React 18 + Vite + Tailwind
- LLM: Anthropic Claude(`claude-sonnet-5`) — `LLMProvider` 어댑터 뒤, Bedrock 교체 가능
- 경로: Google Routes API v2 — `RouteProvider` 어댑터 뒤, 국내 ODsay 참조 구현
- 장소: Google Places API (New) 수집 → LLM 사전 배치 태깅
- **런타임 LLM 호출은 대화 1건당 1회뿐**, 일정 생성은 0회(결정적 알고리즘)

## 5. 데이터 활용

| 데이터 | 규모 | 가공 | 품질 관리 |
|--------|------|------|-----------|
| Google Places (파리·타이베이) | 도시당 135곳 (5유형 쿼터) | 영업시간·유형 정규화, 리뷰 10건 미만 제외 | 30일 재수집(약관) |
| LLM 5축 태깅 | 270건 | 메타데이터만 입력(리뷰 미사용) | **수동 검수 30건 통과**(87%) — [TAGGING_REVIEW.md](TAGGING_REVIEW.md) |
| Google Routes v2 | 요청 시 실시간 | 편성 시각·운영기관·요금·대안 경로 | 저장 안 함, Haversine 사전 필터로 호출 절감 |
| 가짜 카톡 대화 | 5종 | 데모·회귀 테스트 입력 | 5축 근거·제약·갈등 케이스 포함 설계 |

도시 선정 자체가 데이터 검증의 산출물이다: 도쿄·오사카는 Routes API 가 TRANSIT 경로를 주지 않아
호출로 판정 후 제외했다([DECISIONS.md](DECISIONS.md) 2026-09-06).

## 6. 실측 결과

### 6-1. maximin vs 평균 — 실데이터(파리 수집본 135곳)

정답지 대화 `02_conflict`(정반대 취향 3인)의 프로필로 후보 순위를 두 방식으로 매겼다
(`python scripts/compare_maximin.py`).

| 지표 | 평균 방식 | 정규화 maximin |
|------|:---------:|:--------------:|
| 상위 10곳 겹침 | — | **0 / 10** |
| 상위 10곳의 "가장 불만족한 멤버" 만족도 평균 (파리) | 48% | **65%** |
| 같은 지표 (타이베이) | 52% | **66%** |

평균 방식 상위권은 한 사람이 매우 좋아하고 다른 사람은 싫어하는 장소로 채워졌다. maximin 은
세 사람 모두 "나쁘지 않은" 장소를 고른다 — 그룹 여행에서 한 명이 소외되는 일을 막는 것이 목적이다.
