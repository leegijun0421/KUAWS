# itinerary-scheduler — 요구사항

> 상태: 구현 완료 (2026-09-27). 코드 `backend/planner/`, 테스트 `tests/test_planner_*.py`.

## 목표

매칭된 후보 POI 를 실제 대중교통 시간표 위에 올려, 제약을 지키는 "항상 그럴듯한" 일차별 일정을 만든다.

## 기능 요구사항

| ID | 요구사항 | 수용 기준 |
|----|----------|-----------|
| IS-1 | 탐욕 배치 + 실패 시 하위 후보 제거 재시도 | 최대 3회, 그래도 실패면 빈 일정 대신 사유(`failure_reason`) 반환 |
| IS-2 | 실경로 기반 시각 | 구간마다 `plan_segment(depart_at=현지 RFC3339)` 로 실제 편성 시각 사용 |
| IS-3 | 요일별 영업시간 | Google `weekdayDescriptions` 를 요일별 구간으로 해석, 도착 후 30분 이상 머물 수 있어야 배치 |
| IS-4 | 12시·18시 식사 강제 | 점심 11:30~13:30·저녁 18:00~20:00 에 식사 장소 우선, 시간대 밖 식사 금지, 45분 대기 허용, 못 채우면 경고 |
| IS-5 | 하루 이동시간 상한 | 기본 180분, 활동량 최저 멤버 < 0.35 면 120분. 80% 초과 시 경고 |
| IS-6 | 막차 경고 | 도시 막차 시각(`common/cities.py`)과 그날 마지막 탑승 편성 시각의 여유 < 45분이면 경고. 편성 시각 없으면 추정하지 않음 |
| IS-7 | 호출 절감 | 추정치로 제약 사전 검사 후 상위 3개만 라우팅. 800m 이하 도보·40km 초과 제외는 호출 0회 |
| IS-8 | 관광 스톱 상한은 pace 로 | 그룹 평균 pace ≥ 0.6 → 6곳, ≥ 0.35 → 5곳, 그 외 4곳. 식사는 상한에 세지 않음 |
| IS-9 | must_visit 우선 | 꼭 가고 싶은 곳은 점수 1.0 + 동점 시 맨 앞 |
| IS-10 | 실패 위험도 | 스톱마다 객관 지표 기반 확률과 근거(`planner/risk.py`). 인기도·혼잡도 미사용 |

## 범위 밖

- 최적해 탐색(조합 최적화) — 의도적으로 하지 않는다(ARCHITECTURE 5.4)
- 숙소 위치·귀가 경로 — 예선 범위 밖(막차 경고는 그날 마지막 이동 기준)
- 택시 대안(절단 2) — 본선

## 미결 사항

- [ ] `travel_penalty`(0.25/h)·스톱 상한은 외부인 테스트 피드백으로 조정
