# preference-intake — 요구사항

> 상태: 초안 (담당자 검토 필요)

## 목표

여행 참가자 각자의 취향을 자유 텍스트로 받고, 표현이 모호하면 정량 입력으로
보강하여 **구조화된 취향 프로필**을 만든다.

## 사용자 스토리

- 참가자로서, 긴 문장으로 "바다 보이는 조용한 카페 좋아하고 사람 많은 데는 별로"
  라고 쓰면 시스템이 알아서 이해했으면 좋겠다.
- 참가자로서, 내가 쓴 내용이 애매할 때 시스템이 다시 물어봐 주면 좋겠다.
- 참가자로서, 답하기 어려운 질문은 슬라이더나 선택지로 빠르게 답하고 싶다.

## 기능 요구사항

| ID | 요구사항 | 수용 기준 |
|----|----------|-----------|
| PI-1 | 자유 텍스트 취향 입력을 받는다 | 10자 이상 입력 시 프로필 초안 생성 |
| PI-2 | LLM이 텍스트에서 취향 축 값을 추출한다 | 정의된 축 전체에 대해 값 또는 `unknown` 반환 |
| PI-3 | 값이 `unknown`이거나 신뢰도가 낮으면 후속 질문을 생성한다 | 최대 3회까지 추가 질문 |
| PI-4 | 후속 질문은 슬라이더 또는 선택지 형태로 정량 응답을 받는다 | 응답이 즉시 프로필에 반영됨 |
| PI-5 | 사용자는 대화를 계속 이어가며 프로필을 수정할 수 있다 | 이전 대화 맥락 유지 |
| PI-6 | 완성된 프로필은 그룹 단위로 집계된다 | 참가자 N명의 프로필 배열 반환 |

## 범위 밖

- 익명 입력 (팀 회의에서 제외 확정)
- 계정/친구 시스템 — 링크 접근만 지원
- 실시간 동시 편집

## 비기능 요구사항

- LLM 1회 호출 응답 시간 5초 이내. 초과 시 로딩 상태를 UI에 노출.
- 동일 입력에 대한 LLM 결과는 캐싱하여 중복 호출을 막는다.
- LLM이 JSON 파싱에 실패하면 1회 재시도, 그래도 실패하면 정량 입력 폼으로 대체한다.

## 미결 사항 (담당자가 채울 것)

- [ ] 취향 축을 몇 개로 할 것인가 (권장: 5~7개)
- [ ] 각 축의 이름과 양 끝 라벨
- [ ] 신뢰도 임계값을 얼마로 둘 것인가
